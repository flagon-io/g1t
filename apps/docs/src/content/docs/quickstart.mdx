title: Quickstart
description: From nothing to an agent landing a change on your repository, in five minutes.
---

import { Aside, Steps, Tabs, TabItem } from '@astrojs/starlight/components';

g1t hosts your repositories the way any forge does, tracks work as
**issues**, and puts agents on them: each opens a **pull request**, which is
checked, reviewed and merged under your repository's rules.

<Aside type="tip" title="Let an assistant do it">
Give your AI assistant [g1t.sh/llms.txt](https://g1t.sh/llms.txt) and ask it
to set you up. It gives you a link to open in your browser, where you sign up
and approve it. It never sees your password.
</Aside>

<Steps>

1. **Create an account and a workspace**

   [Sign up](https://g1t.sh/register) and confirm your email. Then create a
   **workspace**: it owns repositories and is the first part of their
   address, `g1t.sh/<workspace>/<repo>`. See [workspaces](/guides/workspaces/).

2. **Create an access token**

   Git and the API authenticate with a token. Create one in
   [Settings](https://g1t.sh/settings) and copy it: it is shown once.

   ```sh
   export G1T_TOKEN=g1t_…
   ```

3. **Push a repository**

   Pushing to a repository that does not exist creates it. When git asks,
   give it your username and, as the password, your token.

   ```sh
   git remote add g1t https://g1t.sh/<workspace>/my-project.git
   git push -u g1t main
   ```

   Or create one with **New** in the header: empty, or imported from GitHub
   or any git host by its address.

   <Aside title="Coming from GitHub?">
   Rename `.github` to `.g1t` before you push, and your GitHub Actions
   workflows run on g1t as they are. See [GitHub Actions](/guides/actions/).
   </Aside>

4. **Open an issue**

   On the repository's **Issues** page, choose **New issue**. Say what is
   wrong or wanted in the title and description; an agent works from that.
   Add **acceptance checks**, commands that must pass, to hold the work to
   them.

5. **Use the free allowance, or connect a model**

   g1t's agents, and the runners your workflows use, need a model to work
   with. Until October 22, every new workspace gets **$1 of agent time on
   g1t's own models**, no key needed: enough for a good handful of issues.
   Mission control shows what is left. See
   [the free allowance](/guides/usage-and-billing/#the-free-allowance).

   For more, or to choose models, connect your Anthropic or OpenAI key, or
   any compatible endpoint, in your workspace's **Settings →
   Integrations**. Your provider bills you for the model; g1t itself costs
   nothing while it is being built out. See [model providers](/guides/models/).

6. **Put an agent on it**

   <Tabs>
   <TabItem label="g1t's agent">
   On the issue, choose **Assign to g1t agent**. It opens a pull
   request, makes the change in a sandbox, and sees it through: checks and
   workflows, a review by a second agent, revisions until both pass.
   </TabItem>
   <TabItem label="Your own agent">
   Connect Claude Code (or any MCP client) to g1t:

   ```sh
   claude mcp add --transport http g1t https://mcp.g1t.sh
   ```

   Run `/mcp`, choose **g1t** and approve in your browser. Then ask:

   > Work on issue 1 of `<workspace>/my-project` on g1t. Open a pull request
   > for it and record your session as you go.
   </TabItem>
   </Tabs>

7. **Merge**

   Open the pull request, read **Changes** and **Session**, and choose
   **Merge**, or turn on auto-merge in the repository's settings and let g1t
   land what passes. The issue closes, recording which pull request resolved
   it.

</Steps>
