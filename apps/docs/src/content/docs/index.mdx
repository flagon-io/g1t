g1t is the code platform your team and your own coding agents work on.
**Code** holds your repositories, issues and pull requests, with required
checks, the merge queue and Actions; **Deployments** puts every pull request
live on a preview and ships production on merge. Your team talks in
**Chat**, writes docs together in **Artifacts**, and **Home** tells you
where you're needed and what happened while you were away.

Bring the coding agents you already use, such as Claude Code, Codex,
Cursor or OpenCode. They connect over [MCP](/guides/bring-your-own-agent/)
and work as you: they pick up issues, open pull requests, run your checks,
record their sessions, and read and write the project's memory.

g1t is MIT-licensed. You can use it on g1t.sh, or run it yourself.

<Aside type="note" title="g1t is in alpha">
Accounts are by invite while the alpha runs. Every feature on these pages
is marked with where it stands:

- <Status is="live" /> works on g1t.sh for every workspace.
- <Status is="preview" /> works on g1t.sh, but is limited to some workspaces
  or not finished. Its page says how.
- <Status is="coming" /> is planned and not built yet. Nothing on a page
  marked Coming works today.

[What g1t can't do yet](/about/limitations/) lists the limits you can hit.
</Aside>

## The workspace

Everything happens in a workspace: your company, or one team in it. The
rail down the left holds Home, Chat, Notifications, Code and Artifacts, the apps you pin, and People, Workspace and your account at its
foot. On a phone it is a bar along the bottom.

| Feature | What it does | Status |
| --- | --- | --- |
| [Home](/guides/home/) | The front page: where you're needed now, what happened since you were last here, what is running, and where to start. | <Status is="preview" /> |
| [Chat](/guides/chat/) | Channels, direct messages and threads, live. No seats and no history limit. | <Status is="live" /> |
| [Notifications](/guides/notifications/) | Everything waiting on you: mentions, reviews, approvals and alerts, with browser push. | <Status is="live" /> |
| [People and teams](/guides/people-and-teams/) | Everyone in the workspace in one search, with profiles and teams. Members, roles, nested teams and invites. | <Status is="live" /> |
| [Artifacts](/guides/artifacts/) | Documents written together, live, by your team and the coding agents you connect. Private until you share them. | <Status is="live" /> |
| More kinds of artifact | Slides, designs and dashboards that keep the query behind every number. | <Status is="coming" /> |
| Scratchpads | Tools and reports anyone can build on a copy of the data, used in production only after review. | <Status is="coming" /> |
| [The desktop app](/guides/desktop/) | g1t in a window of its own for Windows, macOS and Linux, with notifications from your system. | <Status is="preview" /> |
| [The phone app](/guides/mobile/) | Chat with your team, live, with notifications on the phone; review pull requests. Android first, for g1t.sh or your own g1t; not in the stores yet. | <Status is="preview" /> |
| [A runner in the desktop app](/guides/desktop/#the-runner) | Your workspace's self-hosted jobs on your computer while g1t is open, registered and kept up to date by the app, sandboxed by default: Linux jobs in a sandbox of the runner's own on Windows, macOS and Linux, and Windows jobs in Windows Sandbox on Windows 11 Pro and up. | <Status is="preview" /> |

## Code and Deployments

| Feature | What it does | Status |
| --- | --- | --- |
| [Repositories](/guides/managing-repositories/) and [git](/guides/git/) | Public and private repositories over HTTPS, with creating one by pushing to it. | <Status is="live" /> |
| [Issues and pull requests](/guides/pull-requests/) | Issues, pull requests, line comments and reviews. | <Status is="live" /> |
| [Checks](/guides/checks/), [rules](/guides/rules/) and the [merge queue](/guides/merge-queue/) | Required checks, protected branches, code owners, and changes tested together before they land. | <Status is="live" /> |
| [Workflows](/guides/actions/) | Workflows from `.g1t/workflows`, most unchanged, on g1t's runners or [your own](/guides/self-hosted-runners/). | <Status is="live" /> |
| [Connect a coding agent](/guides/bring-your-own-agent/) | Any coding agent or MCP client works on g1t as you and records its session onto its pull requests. | <Status is="live" /> |
| [Memory](/guides/memory/) | What a project and a workspace remember, read and written by people and by your coding agents. | <Status is="live" /> |
| [Packages](/guides/packages/) | npm, Cargo, Composer, Maven, NuGet, RubyGems, Go modules and container images. | <Status is="live" /> |
| [Security](/guides/security/) | Secret push protection, history scanning and pull requests that upgrade vulnerable dependencies. | <Status is="live" /> |
| [Deployments](/guides/deployments/) | A live preview of every pull request on g1t.page, production on merge, and custom domains. | <Status is="live" /> |
| Preview data | Each preview gets its own copy of the database and bucket, deleted when the pull request closes. | <Status is="coming" /> |
| [Docker deployments](/guides/deployments/#docker-deployments) | Any app with a Dockerfile, or a Node.js, Python, Go, Ruby or PHP server, runs as a container that sleeps when no one visits. | <Status is="live" /> |
| [Observability](/guides/observability/) | Requests, logs, traces, metrics and grouped errors, by deployment: from apps on g1t.page with nothing to set up, and from anywhere else over OpenTelemetry. | <Status is="live" /> |
| Rollback and always on | One click back to any deploy, and container apps kept warm. | <Status is="coming" /> |
| [GitHub](/guides/github/) | Import repositories with every branch and tag, and their issues. | <Status is="live" /> |
| Git over SSH | `git@g1t.sh` remotes. Use HTTPS until then. | <Status is="coming" /> |

## Using an AI assistant?

Give it [g1t.sh/llms.txt](https://g1t.sh/llms.txt), which describes g1t for
agents, and ask it to set you up, or [connect it](/guides/bring-your-own-agent/)
so it can work on g1t itself. Every page here also has **Copy page** at
the top, to paste into a conversation, and a plain Markdown version at its
address plus `.md`.
